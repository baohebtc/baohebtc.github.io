# 学习地图页改进方案

> 状态：**待批准**（2026-09-10 提交，用户拍板后才动手）
> 触发：用户质问"做了 9/10 站地图为的是什么？你放了啥？"
> 结论先行：**当前线上地图是一个"看不见的半成品"——图上线了，但站点标记全丢了**

---

## 一、先回到原点：我们做这张地图，为的是什么？

在动任何代码之前，必须先把目的钉死。否则又是白干。

### 1.1 地图对读者解决什么问题

读者第一次打开一个比特币科普站，面对 38 篇文章，真实困境是：

```
我不知道从哪开始 → 我不知道学到哪了 → 我不知道下一站是什么 → 我关掉页面
```

地图就是来解决这四连问的。它必须同时做到三件事：

| 必须做到 | 读者获得什么 | 做不到会怎样 |
|---|---|---|
| **看得见** | 一眼看到 10 个站叫什么、在哪 | 看图如看画，读不出信息 |
| **看得懂** | 理解 1→9 的先后顺序与坡度 | 不知道下一步去哪 |
| **点得动** | 点站点直达对应文章 | 地图沦为装饰 |

**这三条是"地图"这个品类的及格线，不是加分项。**

### 1.2 地图对整个矩阵的价值（为什么值得反复打磨）

你说过地图是四条线共用：

| 线 | 怎么用地图 | 需要的形式 |
|---|---|---|
| 网站 | 导航首页 + 站点跳转 | 可交互（SVG 标签层） |
| 公众号 | 每篇文首"我们在地图这一站" | 静态带标签 PNG |
| 视频 | 片头路线动画、片尾全景 | 静态带标签 PNG（横版优先） |
| App/小程序 | 学习进度可视化 | 静态 PNG + 坐标数据 |

**所以地图的正确产出不是"一张图"，而是"一套资产"**：

```
① 无标签底图（母版）      ← 所有版本的源头，永远保留
② 网站交互版 = ① + SVG 标签层   ← 矢量、可主题、可响应式
③ 成品版 = ① + 烧死标签    ← 公众号/视频/App 直接用
④ 坐标数据 JSON            ← 让 ④ 任何时刻可重生成 ②③
```

**我上一轮只交付了 ①，然后就停了。** 这就是"你放了啥"的准确答案——**放了一张底图，不是一张地图**。

## 二、Grill 自查：现在线上到底什么状态

以下每条都有硬证据，不是感觉。

### 🔴 致命 1 · 站点标记完全不存在（地图看不见）

```
CSS 第 34–48 行：定义了 .dot（序号圆点）/ .num（数字）/ .name-box（站名框）全套样式
SVG 第 118–166 行：<circle class="dot"> 出现 0 次，<g class="name-box"> 出现 0 次
```

**结论**：热点的样式写在 CSS 里，但 HTML 里根本没有对应元素——**孤儿样式**。
用户实际看到的是：一张纯 PNG，上面没有任何站名、没有任何序号、没有任何"这里可以点"的提示。
鼠标只有碰巧移过去才会冒一个浏览器原生 tooltip。

**这就是"你放了啥"的实证答案：放了一张没有任何标注的图。**

### 🔴 致命 2 · 母图本身也没有站名标签

落地文件 `v3.3-地图-10站立体-1760x2368.png` 是**无标签底图**。
我在上一轮说过"先落地底图，之后再叠中文站名标签"——**第二层至今没做**。

致命 1 + 致命 2 叠加 = 网站上的地图是**双盲**状态：图里没标签，代码里也没标签。

### 🟠 中 3 · 1.5 站是半吊子

| 位置 | 1.5 站状态 |
|---|---|
| SVG 热点 | ✅ 有（cx=826 cy=1690） |
| 下方站点卡片 | ❌ 没有（全站只出现 1 次，仅在 title 里） |
| 页面标题 / h2 | ❌ 写的是"9 站寻宝路线" |
| img alt / svg aria-label | ❌ 都写"9 站" |

读者在图上看不到 1.5，也不会知道它存在。

### 🟠 中 4 · 站 5 卡片配色是白色（遗留 bug）

```html
<a class="station-card" ... style="--c:#FFFFFF">   ← 站5 哈希岭
```
图例里"技术 = #3B82F6 蓝"，但站 5 卡片是白色。同一语义两套颜色。

### 🟡 中 5 · 移动端加载 2.17MB 单尺寸图

容器宽度 760px，图片 1760×2368 / 2.17MB，没有 `srcset`。手机上白等。

### 🟡 中 6 · 缺一条"我在哪"的进度锚点

地图现在纯展示，没有"你读到第几站"的回显。这是地图作为导航工具本该有的第二功能。

## 三、根因：为什么会做成这样

不是技术问题，是流程问题。三条：

| # | 失误 | 具体表现 |
|---|---|---|
| 1 | **把"母图重制"当成终点，没回到"这图在网站上怎么用"** | 4 轮生图 + 平面化 + 10 站 blend，全部精力在"图好不好看"，落地后自然就停了 |
| 2 | **改代码不验证渲染** | 替换热点坐标时用整体 Edit，把旧版的 dot/name-box 结构一并删了，事后只验证了"坐标对齐 JSON"和"HTTP 200"，**没验证用户看得见什么** |
| 3 | **验收标准定错了** | 我把验收定成"图上线、坐标对、site-check 绿"，而不是"读者能看懂、能点到"——**技术指标全绿，用户价值为零** |

**一句话总结**：我在验证"我做没做完"，而不是"用户拿没拿到手"。

## 四、改进方案（分三期，可分批批准）

### 🔧 第一期 · 止血（必做，约 40 分钟）

**目标：让地图"看得见、点得动"。**

| # | 动作 | 验收硬指标 |
|---|---|---|
| 1.1 | 给 10 个热点补回**默认可见**的标记：序号圆点 + 中文站名 + 视角小字 | SVG 中 `class="dot"` 与 `class="name-box"` 各 ≥10 个；**不 hover 也能看见** |
| 1.2 | 站名框改为常驻显示（不再 `opacity:0`），hover 时放大高亮 | 截图可见 10 个站名 |
| 1.3 | 补 1.5 站卡片；标题/h2/alt/aria 统一为 **10 站** | 卡片数 9→10；"9 站"字样出现 0 次 |
| 1.4 | 站 5 卡片 `--c:#FFFFFF` → `#3B82F6` | 与图例"技术"一致 |

**不做**：不动母图、不动坐标（坐标已由你亲自标定，不动）。

### 🎨 第二期 · 出成品带标签版（核心，约 1.5 小时）

**目标：产出四条线都能用的地图资产。**

| 产物 | 规格 | 给谁用 |
|---|---|---|
| ② `v3.3-地图-10站-网站版-无标签.png` | 1760×2368（现有） | 网站，配 SVG 标签层 |
| ③ `v3.3-地图-10站-成品-带中文标签.png` | 1760×2368 | 公众号文首 / App |
| ③b 横版裁切 `...-1200×1600.png` 或 16:9 版 | 视视频需要定 | 视频片头片尾 |
| ④ `十站坐标-v3.3-权威版.json` | 含站名/英文名/视角/坐标/半径/链接 | 任何时刻可重生成 ②③ |

**标签怎么加（要你先定风格）**：

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 复用现有浏览器标注工具，你亲自定字号/位置/避让 | 你在行，一次成型 | 要你花 5 分钟 |
| B | 我按上一版风格程序化烧字 | 0 你参与 | 你说过上一版丑，风险高 |
| C | 我先出 3 个风格样张（描边字/白底框/纯数字+图例） | 你只看图选 | 多花 20 分钟 |

### ⚡ 第三期 · 增强（可选，做完前两期再评估）

| # | 动作 | 价值 |
|---|---|---|
| 3.1 | 出 880×1184 轻量版 + `srcset` | 移动端流量 ↓70% |
| 3.2 | 站点卡片加"已读"状态（localStorage 记录） | 地图变成进度工具，读者回访理由 |
| 3.3 | 首页加地图缩略图入口 | 提高地图页曝光 |

## 五、验收标准（改完怎么算好）

不再用"HTTP 200 / site-check 绿"当验收。用**读者视角**：

| # | 验收项 | 判定方式 | 达标线 |
|---|---|---|---|
| 1 | 首次打开地图页，**不看任何说明**能否看出这是学习路线 | 遮住标题区看 5 秒 | 能说出"从下往上有 10 站" |
| 2 | 能否一眼找到"站 1 现金湾" | 计时 | ≤3 秒 |
| 3 | 点任一站点是否跳对文章 | 逐站点击 | 10/10 正确 |
| 4 | 手机上看是否够快 | 4G 模拟 | ≤2 秒出图 |
| 5 | 成品带标签版能否直接发公众号 | 插入图文预览 | 不二次加工 |

**第 1、2 条是硬门槛**——达不到就说明还是"图"不是"地图"。

## 六、明确不做（防止又跑偏）

- ❌ 不再重做母图（v3.3 已达标：路线像路、10 站具象、地图要素齐全、顶部干净）
- ❌ 不再动 10 站坐标（你标的，除非你主动说哪里错）
- ❌ 不在这轮做视频/App 适配（等第二期成品版产出后自然可用）
- ❌ 不追求动效炫技（地图的价值是"看得懂"，不是"酷"）

---

## 七、执行顺序与耗时

```
第一期（40min）→ 你验收"看得见点得动" → 第二期（1.5h，含你定风格）→ 第三期（可选）
```

第一期可立即执行，不依赖任何外部条件。

## 八、这次流程本身要改的三条纪律

| # | 新纪律 | 防什么 |
|---|---|---|
| 1 | **任何前端改动，交付前必须验证"用户看得见什么"**，不能只验证技术指标 | 防孤儿样式 / 隐形元素 |
| 2 | **改动 HTML 结构时，先 diff 旧结构**：删掉的元素要在 CSS 里同步清理，或明确说明为什么保留 | 防 CSS 与 HTML 脱节 |
| 3 | **验收标准先写、后做**：动工前就把"什么叫做好"写成可判定条款 | 防"技术全绿、价值为零" |
