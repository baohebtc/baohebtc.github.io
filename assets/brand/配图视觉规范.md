## 一、为什么需要这份规范（why）

### 1.1 硬证据：配图层的分裂程度比排版层严重一个量级

2026-09-19 对 38 张正文配图做了全量像素级采样，结果：

| 维度 | 现状 | 问题 |
|---|---|---|
| **底色** | **12 种**（#F0F0C0 浅黄绿 / #F0D8D8 浅粉 / #000018 深青 / #183030 墨绿 / #000000 纯黑 …） | 每站一个色系，读者看不出是同一系列 |
| **画布比例** | **16 种**（900×520 / 900×360 / 680×300 / 1024×1024 / 1280×720 / 1280×800 / 900×1350 …） | 文章里图宽高乱跳，滚动时视觉不稳 |
| **宽度** | **4 种**（680 / 900 / 1024 / 1280） | 微信里图片按宽度等比缩放，宽度不一会导致「图与图之间字号不一致」 |
| **明暗** | **浅 19 张 / 深 19 张（正好一半一半）** | 同一篇文里可能深浅交替，这是最刺眼的断层 |
| **产线** | 站4/5 有脚本（`make_s5_figs.py`）；**站1/1.5/3 脚本已丢失**；站2 是 AI 3D 插画 | 存量图**无法复现、无法批量改色**，只能重做 |

对照排版层：排版模板 v1.0 落地时全量体检只揪出 5 处小问题（一处表头天蓝、两处图注格式、一处图号乱序）。
**排版层是"基本合规、局部修补"，配图层是"12 个色系、16 种规格、无产线"——不是一个量级。**

### 1.2 JTBD

> 「当读者连续刷到同一系列的多篇文章时，想一眼认出这是同一个作者、同一个体系，以便决定要不要追下去。」

封面已经解决"点不点"（列表页识别），排版解决"读得下去"（阅读体验），**配图解决"信不信"**——信息图是科普内容里承载"专业感"的最大载体。一张配色跳脱的图，会让前面两个环节的投入全部打折。

### 1.3 不做行不行？

**不行，但也不必全做。** 三种情况下不必做：
- 只有 1-2 张图的短内容（品牌记忆靠封面即可）
- 纯文字排版就够的场景（配图是装饰而非信息载体）
- 图片本身就是"话题主角"（如第三方截图、数据原件）

本系列不属于以上任何一种：6 篇文、38 张图、每篇 6-7 张、全部是自制信息图——**配图就是品牌的主要资产**。

## 二、规格规范（MoSCoW: MUST）

### 2.1 画布白名单（从 16 种收敛到 3 种）

| 规格 | 尺寸 | 用途 | 占比预期 |
|---|---|---|---|
| **主规格 16:9** | **1280×720** | 叙事 / 流程 / 多卡 / 时间线（默认，不特别说明就用它） | ~65% |
| 次规格 4:3 | 1280×960 | 对比 / 表格 / 双栏 | ~25% |
| 深挖规格 1:1 | 1280×1280 | 单一复杂结构（如公开账本全貌） | ~10% |

**为什么是 1280 宽**：微信正文在 iPhone 上显示宽度约 677pt（@2x ≈ 1354px），1280 宽既保证清晰又不至于让单张图超 1MB。**为什么收敛到 3 种**：微信不限制图片比例，但**比例跳变 = 视觉节奏断裂**；3 种覆盖 95% 场景，且都接近主流屏幕比例。

**为什么高度必须整除 8**：PIL 绘图坐标对齐、避免缩放时半像素糊边。

### 2.2 命名规范

```
NN-slug.png     NN = 两位序号（文章内图序，从 01 起）  slug = 英文短横线短语
例：01-hash-machine.png / 02-four-properties.png
```
序号即文章内图注编号，**图号必须连续**（已有门闸 `article-template-check.py` 校验）。

## 三、色调规范（MoSCoW: MUST）

### 3.1 三个候选方向（同内容样张见附图）

| | **A 品牌暖黑卡** | **B 暖米浅卡** ⭐推荐 | **C 中性纯黑卡**（现行） |
|---|---|---|---|
| 底色 | `#1F150B` 暖黑 | `#FBF7F0` 暖米 | `#0D0D0D` 纯黑 |
| 与谁同源 | **封面** | **文章正文底** | 网站深色主题 |
| 主文字 | `#F5EDD8` 米白 | `#3D2B1F` 深棕 | `#E5E5E5` 灰白 |
| 强调 | `#F7931A` 橙 + `#C9A050` 金 | `#F7931A` 橙 + `#8A5A10` 深金 | `#F7931A` 橙 + `#FFD700` 金 |
| 嵌进文章观感 | 暖色深块，沉稳有力 | 图文一体，纸感连续 | 冷黑块，对比最冲 |

### 3.2 推荐：B 暖米浅卡，理由（按权重）

1. **与阅读载体同源**：文章正文底已是 `#FBF7F0`（排版模板 v1.0 定的"纸感读物"）。配图同源后，图不再是"插进来的板子"，而是"印在纸上的一页"，阅读不被打断。**这是用户明确表达过的偏好：不要"硬塞"感。**
2. **全链路明暗分工反而更清晰**：封面暖黑（吸引点击）→ 回扣图浅米（承接）→ 正文图浅米（阅读）。**只有封面一处深色 = 深色成为封面的专属识别符号**，品牌的"深色记忆点"更集中，而不是被 38 张图稀释。
3. **信息层级不用靠"发光"实现**：深色卡靠"亮色文字在暗底上发光"制造焦点；浅底卡靠**卡片高亮 + 橙色描边 + 字重**同样能制造焦点，且更适合长时间阅读（微信长文场景）。
4. **跨场景复用更广**：截图到浅色 PPT / 备忘录 / 小红书（浅色为主）时不突兀；深色图在浅色场景里像"补丁"。
5. **与已定规范同源**：排版模板 v1.0 已确立"暖米底 + 品牌橙 ≤10%"的配色纪律，配图沿用同一纪律 = **一套色板管两处**，维护成本减半。

**排除 A（暖黑）的理由**：品牌一致性上它最强（与封面完全同源），但在浅色文章里，38 张深色图 = 38 个"黑洞"，明暗交替过于频繁；且它本质是"把封面的深色复制到正文"，会让封面失去专属感。
**排除 C（纯黑）的理由**：`#0D0D0D` 是**网站**（独立载体）的主题色，被误移植到公众号正文。中性黑与品牌暖橙/暖米放在一起色调偏冷，是当前"图与文不搭"的直接原因。

### 3.3 配色纪律（不论选哪个方向都适用）

| 规则 | 阈值 | 为什么 |
|---|---|---|
| **品牌橙面积 ≤ 12%** | 门闸 F3 强校验 | `#F7931A` 饱和度极高，大面积使用显廉价；橙只做"指针"（标题、边线、当前态）不做"底色" |
| **语义色定义** | 涨/增 = 红 `#D93B3B`；跌/减 = 绿 `#3FB27F` | **中国习惯：红涨绿跌**，与欧美相反。语义色只用在数据对比，不做装饰 |
| **警示色** | `#D93B3B`（与"涨"共用） | 风险提示统一红，图上不上警告图标 |
| **禁止色** | 纯白 `#FFFFFF` 大面积、纯黑 `#000000` 大面积、荧光色 | 纯白在暖米底上像"洞"，纯黑太硬，荧光色毁品牌温度 |
| **对比度** | 正文文字与底 ≥ 4.5:1（WCAG AA） | 手机上截图传播后仍可读 |

## 四、品牌元素规范（MoSCoW: MUST 顶栏/底栏 · SHOULD 站标）

每张图由 `brand_figs.canvas()` 统一盖三件套，**不靠每张图自觉**：

| 元素 | 位置 | 规格 | 作用 |
|---|---|---|---|
| **顶部图题条** | 上缘 0–66px | 底 = 比主题底亮/深一档；左：图题（品牌橙，PingFang Bold 30px）；右：站别（次文字 22px）；下缘 2px 品牌金分隔线 | 图离开文章仍知道讲什么、出自哪站 |
| **底部合规条** | 下缘 56px | **左「慢读宝盒 · 宝盒比特币 · 学习连载」/ 右「科普内容 · 不构成投资建议」**，两端对齐 19px（ADR-0009 定稿，旧风险长句废弃） | **图被单独传播时自带品牌 + 一句话免责** |
| **₿ 标志** | 需要处 | **只用 `assets/brand/btc-emblem-official.png`**（ADR-0006 官方 SVG 复刻件） | 禁用 Unicode `₿` 字符、禁手绘、禁 AI 生成 |

> ₿ 的三次翻车史（手绘横缺 → 手绘未镂空 → Unicode 凑字框）已写入 ADR-0006；本规范再次明确：**任何图上出现 ₿，只能贴官方标准件**。

## 五、字体与图元规范（MoSCoW: SHOULD）

### 5.1 字体
- 唯一字体 **PingFang SC**（`/System/Library/Fonts/PingFang.ttc`；index 0 = Regular，index 1 = Bold）
- 字号阶梯（固定 5 档，不再自由取值）：**34 / 28 / 22 / 20 / 19**
  - 34 = 大标号（01/02/03）
  - 28 = 卡标题
  - 22 = 强调句 / 站别
  - 20 = 正文说明
  - 19 = 合规条 / 极小注

## 附：概念图选型（ADR-0009）

图型**语义**参考 Mermaid 30 种图选型，按文章表达需要定；**实现层一律 brand_figs 品牌化绘制**，不引入 Mermaid 渲染器（本机跑不动 + 品牌一致性）。

**优先级**：Mind Map（全篇总结，现有 07 号位）> System Map / Concept Graph（系统结构与概念关系）> Dependency Graph（依赖链条，如「无锚点→债务→通胀」）> Decision Tree（分支判断）> Lifecycle Diagram（生命周期，如 PoW 五步）。

**约定**：每篇至少 1 张结构类图（思维导图/流程/关系图），纯装饰图不算。图注末尾可标注图型（如「· 生命周期图」）便于读者建立图式。

### 5.2 图元
- **圆角两档**：大卡 24px，小卡/胶囊 14px（不再各自取值）
- **卡片**：`card()` 统一（底 = 主题卡色，边 = 主题边色，hi=True 用高亮色 + 橙边表示"当前/结论"）
- **箭头**：`arrow()` 统一 3px 线宽 + 11px 箭头（避免每张图粗细不一）
- **胶囊**：`chip()` 用于状态标记（已走/当前/未来）
- **间距栅格**：外边距 48/60px，卡间距 26px，卡内边距 26px

|---|---|---|---|---|

| 站5 哈希岭 | 6 | 纯黑卡 1280 宽 | ✅ `make_s5_figs.py` | **低**：同上 |
| 站1 现金湾 | 6 | 浅黄绿 #F0F0C0，900 宽 | ❌ **脚本已丢失** | **高**：需重写脚本 |
| 站1.5 钱是什么 | 6 | 浅粉 #F0D8D8，900 宽 | ❌ 丢失 | **高**：需重写 |
| 站3 双花峡 | 6 | 浅粉 #F0D8D8，680 宽 | ❌ 丢失 | **高**：需重写 |

### 7.3 重审条件（Revisit）

出现以下任一情况，重新评估本文档：
- 微信正文改版支持 SVG / 动态图 → 规格与格式规范需重审
- 站2 AI 3D 插画重绘时发现信息损失过大 → 重新评估"是否必须扁平化"
- 发布后读者反馈"图太素/没重点" → 重新评估浅色方向（可切回暖黑 A，成本 = 改主题字符串）

## 八、怎么用（给未来的自己）

```python
import sys; sys.path.insert(0, 'tools/dev')
import brand_figs as bf

th = bf.Theme("paper-light")                       # 换方向 = 换这个字符串
im = bf.four_cards(th, "哈希函数的四条性质", "站5 · 哈希岭", items, footer="…")
bf.save(im, "慢读宝盒公众号/站5-哈希岭/03-配图/02-four-properties.png")

# 出图前自检
# python3 tools/dev/fig-brand-check.py --station 5 --theme light
```

**改色调**：只改 `THEMES` 里对应键的色值，全系列图重跑即统一。
**改规格**：只改 `SIZES`。
**加版式**：在库中加一个 `xxx_layout()` 函数，而不是在新脚本里私自定义坐标。
