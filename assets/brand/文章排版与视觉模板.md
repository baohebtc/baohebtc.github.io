# 慢读宝盒 · 文章排版与视觉模板 v1.1

> 定稿 2026-09-19。与 `design-tokens.md`（色值/₿ 规范）、`视觉品牌统一规范.md`（整体视觉）配套，本文专注**文章内容层**：排版、配色、色调、风格——以及每个选择背后的 why。
> 双载体：**微信正文样式** = `wechat_push.py` 的 `THEME`（用户级 skill `wechat-draft-push/assets/`）；**HTML 备份样式** = `md-to-html.mjs` 的 `STYLE`。改任何样式必须两处同步。

## 一、设计哲学（为什么长这样）

一句话：**「把难的知识，装进宝盒」→ 文章读起来要像打开一个温暖的盒子，不像啃一本技术手册。**

三条派生原则：

| 原则 | 来源 | 落到实处 |
|---|---|---|
| ① 纸感暖底，拒绝纯白 | 宝盒意象 = 旧书/羊皮纸/藏宝图；纯白冷屏感是"工具"，暖米色是"读物" | 正文底 `#FBF7F0` / HTML 页底 `#F3EDE0` |
| ② 品牌橙只做强调，不超过 10% 面积 | ₿ 橙 `#F7931A` 饱和度极高，大面积使用刺眼且显廉价；点缀才显贵（奢侈品逻辑） | 橙只出现在：H2 竖条、引用边条、表头文字、关键加粗 |
| ③ 零装饰噪音 | 科普读者是小白，注意力预算极低；每多一个装饰就少一分理解 | 无背景花纹、无彩色标签云、无动态元素；层级靠**字号+留白+一条橙线** |

## 二、色彩系统（与 why）

### 主色板

| 角色 | 色值 | 用在哪 | 为什么 |
|---|---|---|---|
| 品牌橙 | `#F7931A` | H2 左竖条(3px)、引用块左边条(4px)、关键强调 | 比特币国际官方色，读者 0.1 秒识别题材；**只做细线条不做色块** |
| 正文墨色 | `#3D3D3A` | 正文 | 不是纯黑 `#000`——纯黑在浅底上对比过硬，`#3D3D3A` 柔和约 12% 仍保持 WCAG AA（对比度 10.4:1） |
| 标题深色 | `#2B2B2B` | H2/H3/加粗 | 比正文深一档，形成"标题更实"的重量差 |
| 次要灰棕 | `#9A8C7A` | 图注、em | 低饱和暖灰，"退后但可读"，冷灰在暖底上会显脏 |
| 暖米底 | `#FBF7F0` | 引用块底 / 表头底 | 与封面暖黑、配图米黄同一温度体系 |
| 分隔线 | `#E8E3D9` | hr / 表格边框 | 接近底色的"隐线"，分隔但不打断阅读流 |

### 表头暖金（2026-09-19 从天蓝统一而来）

| 色值 | 用途 | why |
|---|---|---|
| 表头底 `#FBF3E3` | 表格 th | 旧天蓝 `#EAF4FC` 与全站暖色冲突（站4 T2 表图也证明蓝底突兀）；暖金与引用块同底色，全篇只剩一个色温 |
| 表头字 `#8A5A10` | th 文字 | 深金棕，对比度 7.2:1，且暗示"这是重点行" |
| 表头边 `#EBD9B4` | th 边框 | 比内容行边框 `#E8E3D9` 深半档，视觉上"框住重点" |

### 禁用色

- **任何蓝/青/紫冷色**：与品牌暖调冲突（唯一例外：数据语义"正常=绿、警示=红"出现在配图里）。
- **纯黑 `#000` / 纯白 `#FFF` 大面积**：屏幕刺眼；文字一律用墨色系。

## 三、字体与字号阶梯（与 why）

微信正文（THEME）：

| 层级 | 规格 | why |
|---|---|---|
| 正文 | 15px / 行高 1.75 / 字距 0.5px / 两端对齐 | 微信安卓默认 14px 偏小、iOS 17px 偏大，**15px+1.75 是两端机型的公约数**；字距 0.5px 为中文方块字留呼吸缝；两端对齐让中英混排边缘整齐 |
| H2 | 18px 加粗 + 左橙竖条 + 段前 1.9em | 手机上 H2 只比正文大 3px——**层级感靠竖条和留白，不靠字号**（字号拉太大在手机上像喊叫） |
| H3 | 16px 加粗 | 与 H2 保持"半级"差 |
| 图注 | 13px `#9A8C7A` 居中 | 明确的"配角"信号，绝不与正文抢 |
| 表格 | 14px / 行高 1.6 | 表格密度高于正文，字号降 1px 换取不换行 |
| 强调 em | 13px 暖灰、不斜体 | 中文斜体是伪斜（系统强制倾斜），难看；用字号+颜色表达"旁白" |

字体栈：`-apple-system, PingFang SC, ...` —— **跟随系统字体**，不自定义 webfont。why：微信不支持外部字体加载（会降级），强行指定反而双端不一致。

## 四、组件规范

### 0. 标题与副标题（Headline + Deck，2026-09-20 定稿）

**结构**：`主标题（≤12字）+ 分隔符 + 副标题（≤22字）`，全标 ≤34 字。

- **主标题**：优先用站点地名（与封面/回扣图/正文三处一致）；开篇/插篇可用疑问式（如「钱到底是什么？」）。
- **副标题三职能，一篇只选一种**：**路径型**（从X到Y，适合时间跨度大）/ **钩子型**（反直觉问题）/ **范围型**（第几站、覆盖什么）。
- **禁**：重复主标题字眼；剧透答案（副标题只给路径或问题，保住好奇缺口）。
- **分隔符**：统一「：」；主标题以问号结尾时用「｜」（避免「？：」双标点）。
- **正文排版**：`# H1 = 主标题`，紧随其后的引用块行 = **deck 副标题**（推送渲染器自动识别：16px 暖棕 `#8A5A10`、无底块、standfirst 杂志式）。
- **尾板联动**：「下篇预告」书名号内必须写目标篇的**完整标题**（主+副）。

**why**：微信里标题有三个战场——消息列表（约 24 字截断→主标题必须短且前置）、分享卡片（标题是唯一可见文案→必须自解释+承载系列信息）、搜一搜（副标题关键词做差异化）。主标题管打开率（好奇缺口），副标题管交代与导航（连载中途进入的读者靠它定位）。加副标题的反例（不适用我们）：主标题≤12字已讲清钩子+范围；极简短句型账号；副标题写结论剧透。

### 1. 图与图注（本系列最重要的组件）

```markdown
![图 N：一句话标题｜一个关键 takeaway](../03-配图/NN-name.png)
```

- **图注双段式「标题｜要点」**：读者扫图注就能获得 80% 信息，即使跳过正文。这是科普文降低阅读门槛的最大杠杆。
- 图统一圆角 8px、宽 100%、居中；图与上下文间距 1.5em。
- **一图一概念**：一张图只讲一件事，拒绝大而全拼盘图。

### 2. 引用块

米底 `#FBF7F0` + 左橙条 4px + 圆角 6px。用于：类比铺垫、「一句话记住」、风险提示。why：引用块在手机上是唯一能形成"卡片感"的结构，把金句从正文流里托出来。

### 3. 表格

> **硬标准（ADR-0009）**：每篇 ≥1 表格；表格承担「可扫读文本对比」角色，与图（设计卡）互补不重复；5 行以内优先（M5 门闸）。

暖金表头 + 全细边框 + 左对齐。MD 表格行数 >4 时建议改做成配图（如站4 T2、站5 T1 表图）——微信原生表格在窄屏会挤压换行，表图更可控。

### 4. 固定尾板（每篇必有，顺序不可变）

1. 上篇/下篇导航或系列回顾
2. 「关注 慢读宝盒」引导
3. ⚠️ 风险提示（合规硬要求：波动剧烈·仅科普·非投资建议·盈亏自负）

### 5. ₿ 符号使用（ADR-0006）

- 文章内任何 ₿ 图形**只准**用 `assets/brand/` 标准件：深底用 `btc-emblem-official.png` / `btc-symbol-white.png`，浅底用 `btc-symbol-orange.png`，印刷 `btc-symbol-black.png`。
- **禁止**：Unicode 字符 `₿`(U+20BF) 直接排版（双端字体覆盖不一致，会显示成豆腐块或不同字形）、手绘、AI 生成。
- 正文行文里用「比特币」汉字，不用 ₿ 缩写（₿ 只属于图形层）。

## 五、配图风格梯度（现状与路线）

| 站 | 风格 | 底色 | 状态 |
|---|---|---|---|
| 站1 / 站1.5 / 站2 / 站3 | 扁平信息图 | 米黄 `#F7EFD8` 系 | 旧浅色风格 |

| 回扣图 | 矢量寻宝路线 4:3 | 米色 | v3 现行 |

**路线（ADR-0002 仍开放）**：新站一律用深色卡风格；旧浅色图等用户认可方向后批量统一。配色一律以 `design-tokens.md` 为准：暖黑底 + 米白字 + 品牌橙强调（10%）+ 每站一辅助语义色。

## 六、改样式的正确姿势（两处同步 + 验证）

1. 改 `~/.workbuddy/skills/wechat-draft-push/assets/wechat_push.py` 的 `THEME`（微信端）
2. 同步改 `tools/dev/md-to-html.mjs` 的 `STYLE`（HTML 备份端）
3. `wxpush <md> mandu --dry-run` 看日志无错
4. 真实验证：`--update-media-id` 更新一篇草稿，手机预览

**新篇发布前标准动作（门闸链，ADR-0007）**：`content-lint.mjs` → `article-template-check.py`（本模板程序化门闸）→ `article-pub-check.py` → `wxpush` → API 反查 → `mirror-articles.mjs` 双备份。
