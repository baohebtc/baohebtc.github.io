# 开发与试错协议（Git + TDD）

> 核心信念：**git 和 TDD 都是系统化试错工具。**
> TDD 管「动手之前什么算对」（提高命中率），git 管「动手之后怎么退回来」（降低试错成本）。
> 两者合起来只干一件事：**让犯错变便宜**。代价越小，越敢试；越敢试，越快撞到对的做法。
>
> 本协议同时适用于三条产线：写代码、建网页、写文章。写文章也是生产开发。

---

## 一、一次循环（雷打不动的四步）

```
① 定标准（先亮红灯） → ② 最小实现 → ③ 跑检查（红转绿） → ④ commit 存档 → 回 ①
```

三条纪律：

1. **没有失败的检查，就不动手。** 否则你不知道自己在解决什么问题。
2. **绿灯之后立刻 commit。** 安全点密度决定了回退时损失多少。
3. **润色与重构只在绿灯上做。** 红灯状态下改结构等于蒙眼开车。

## 二、Git 协议

### 分支

| 分支 | 用途 | 例 |
|---|---|---|
| `main` | 随时可发布的**绿灯状态**，不在上面做实验 | — |
| `feat/*` | 站点功能 / 新板块 | `feat/collection-hub` |
| `post/*` | 单篇文章创作 | `post/btc-002-blockchain` |
| `fix/*` | 修错 | `fix/nav-mobile-overflow` |

规则：**一个分支只解决一件事**；合回 main 前必须全绿。

### Commit 规范

`type(scope): 主题`，type 取值沿用本仓库既有习惯：

`feat` 功能 ｜ `content` 内容 ｜ `assets` 图片资源 ｜ `docs` 文档 ｜ `brand` 品牌 ｜ `fix` 修错 ｜ `chore` 杂务 ｜ `test` 检查脚本

- 一个 commit 只包含一个意图。改了两件事就分两次提交。
- 主题写「做到了什么」，不写「改了哪个文件」。

### 回退工具箱（试错的退路）

| 场景 | 命令 |
|---|---|
| 看现在改了什么 | `git status` / `git diff` |
| 这条路走死了，扔掉未提交的改动 | `git restore <file>` |
| 半成品先收起来，换条路试 | `git stash` → `git stash pop` |
| 已推送的提交搞错了 | `git revert <sha>`（安全，不改历史） |
| 未推送，想重整最后一次提交 | `git reset --soft HEAD~1` |
| 给发布状态打标记 | `git tag post-btc-001-published` |
| 回看时间轴 | `git log --oneline` |

**禁止**：对 `main` 用 `git push --force`；在有未提交工作时用 `git reset --hard`。

### 双仓库保密（本项目铁律）

| 仓库 | 收什么 | 不收什么 |
|---|---|---|
| 公开 `比特币学习地图/` | 站点代码、图片资产、母库模板、工程文档 | 未发布文章、运营策略、选题弹药库 |
| 私有 `宝盒运营私有/` | 运营规划、品牌手册、公众号策略、工作流 | — |

这条不靠记性，靠 `guard-secrets` 检查（见下）。

## 三、TDD 协议：三层测试金字塔

| 层 | 判定方式 | 内容 | 要求 |
|---|---|---|---|
| **L1 机器可判定** | 脚本，一条命令 | 敏感词、极限词、字数、死链、图片路径、尾板、保密 | **必须自动化，一条都不许靠眼睛** |
| **L2 清单可判定** | 人照单核对 | 每个重要概念有 ✅/⚠️ 类比双段？有配图？多视角？合规九项？ | 照单，不靠记忆和心情 |
| **L3 只能靠品味** | grill 拷问 | 好不好读、类比准不准、开头抓不抓人 | 无法脚本化，靠自我拷问 |

> 关键动作：**把「编辑标准」翻译成「会报错的脚本」。**
> 现在标准散在 `CONTENT-GUIDE.md`、`图文并茂工作流.md`、九项自查里，全靠人记。TDD 化 = 把 L1 那部分变成一条命令：跑一下，红了就是没写完。

> 关于「覆盖尽量多的 Edge Cases」：覆盖边界是 TDD 的**结果**，不是目的。测试越多越脆，改一行全屏红，人就开始删测试。宁要 12 条每次都跑的，不要 200 条没人敢看的。**只测能挡住真实事故的。**

### 计划中的三个检查脚本（放 `tools/dev/`，与读者用的 `tools/*.html` 分开）

1. `content-lint.mjs <file.md>` — 文章 L1：敏感词/极限词、摘要 ≤120 字、尾板齐全、风险提示在、`![]()` 图片路径真实存在、类比双段计数、H2 数量。
2. `site-check.mjs` — 站点 L1：内部相对链接是否都存在、导航项在所有页面一致、每个集合页含免责声明、数据文件字段完整、外链可达性抽查。
3. `guard-secrets.mjs` — 保密 L1：公开仓库暂存区里若出现未发布文章、运营策略、密钥形态字符串，直接非零退出（可挂 git `pre-commit` hook）。

## 四、寻找 Edge Cases 的九个固定提问方向

每次开工前和 grill 时，对着这九条过一遍（不靠灵感，靠清单）：

1. **空与缺省** — 集合页一本书都没有？文章漏图？
2. **边界值** — 摘要刚好 120 / 121 字；标题刚好撑爆封面。
3. **极端量** — 九神集 80 篇时页面还翻得动吗？要不要分页？
4. **顺序与重复** — 一本书属于两个主题，会不会重复收录？
5. **失败与中断** — 外链仓库被删？push 超时半提交？
6. **环境差异** — 微信内置浏览器、暗色模式、无 JS、老安卓、慢网。
7. **语言与编码** — 中文文件名带空格、繁简、术语大小写不统一。
8. **权限与保密** — 私密内容误推公开仓库；密钥进版本历史。
9. **法律与合规** — 转载许可真的允许吗？是否变成投资建议？极限词。

---

## 五、Definition of Done

一件事算「做完」，必须同时满足：

- [ ] L1 脚本全绿
- [ ] L2 清单逐条打勾
- [ ] L3 已 grill 过一轮，且是「为改进而拷问」
- [ ] 九类边界提问过了一遍，发现的问题要么修了、要么明确记录为「已知取舍」
- [ ] commit 已落，信息符合规范
- [ ] 保密检查通过（该进私有的没进公开）

## 六、首个应用：「文集」板块的红灯清单（先写检查，再建页面）

开工时这些应当**先全部是红的**，然后一条条转绿：

- R1 导航在所有页面一致，且包含「文集」
- R2 `collection/index.html` 存在，双轴（主题轴 / 作者轴）均可达
- R3 每个集合页包含统一免责声明：学习资料索引 · 非投资建议 · 观点不代表本号立场
- R4 条目数据字段完整：标题 / 作者 / 类型 / 来源 / 许可 / 一句话导读
- R5 所有外链可达（HTTP 2xx/3xx）
- R6 空集合页显示「整理中」占位，而不是空白页
- R7 无内部死链
- R8 375px 宽度下不横向滚动（L2 人工核对）
- R9 转载类内容保留原署名与许可说明（L2 + 合规）
